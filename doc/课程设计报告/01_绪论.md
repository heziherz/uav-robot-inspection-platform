# 第 1 章 绪论

## 1.1 项目研究背景与意义

### 1.1.1 行业背景

随着低空经济与智能制造的快速发展，无人机与地面移动机器人（机器狗）协同作业正在成为工业巡检与园区安防领域的重要技术形态。传统人工巡检方式存在效率低、覆盖不全、高危区域难以进入等问题：园区围墙外侧、建筑楼道、设备夹层等区域，巡查人员难以到达或存在安全风险。

空地协同巡检通过"无人机高空广域巡查 + 机器狗地面抵近复核"的组合，实现了巡检范围的立体覆盖：无人机凭借视角高、速度快的特点完成大范围快速扫描，发现可疑目标后由机器狗进入楼道、围墙死角等人员与无人机均难以到达的区域完成抵近确认，形成完整的处置闭环。

这一业务形态对软件系统提出了典型的**企业级集成要求**：

- **异构设备接入**：无人机与机器狗的数据模型、上报频率、指令语义各不相同，需要统一的接入与治理机制；
- **高吞吐数据汇聚**：多台设备持续上报位置、传感器、影像元数据与告警事件，数据量随时间线性增长；
- **异构数据存储**：结构化状态数据、时序遥测数据与影像大文件的存储特征差异显著，单一存储介质难以兼顾；
- **实时检索与分析**：需要按设备、时间、类型、地理位置等多维度检索历史事件，并支持统计聚合；
- **指令可靠下行**：任务指令需要准确投递至目标设备并跟踪执行结果。

这些要求恰好对应企业应用集成课程所涵盖的分布式中间件、分布式存储、分布式检索引擎与负载均衡网关等技术组件。

### 1.1.2 项目意义

本项目的实践意义体现在三个层面：

**技术层面**，通过一个完整可运行的业务场景，把课程中分散学习的 Hadoop、MongoDB、Kafka、Nginx、Elasticsearch、Docker 六类组件串联为一条完整的数据链路，理解各组件在系统中的真实位置与协作方式，而非孤立地掌握单项配置。

**工程层面**，实践过程覆盖了多组件版本兼容、容器网络寻址、跨系统路径差异、时序数据建模等典型集成问题。这些问题在单体应用开发中不会遇到，是分布式系统集成所特有的能力训练。

**方法层面**，项目不仅完成功能实现，还通过容量压测与瓶颈定位，建立了"用数据判断系统上限、而非凭感觉估算"的工程方法，理解"加资源"与"改架构"各自的收益边界。

## 1.2 国内外相关技术现状

### 1.2.1 消息中间件

消息中间件是设备接入类系统的核心组件，承担数据汇聚与指令下发的双向通道。当前主流方案包括 Apache Kafka、Apache RocketMQ、RabbitMQ 与 Pulsar。

Kafka 采用分布式提交日志（commit log）模型，以分区（Partition）为并行单位、以顺序写磁盘为持久化手段，在吞吐量上具有显著优势，适合设备高频上报的流式数据场景，且与 Hadoop、Elasticsearch 同属 Apache 大数据生态，集成资料丰富。RocketMQ 由阿里开源，在消息轨迹、延迟消息、事务消息等企业特性上更为完善，中文文档友好。RabbitMQ 基于 AMQP 协议，在路由灵活性上见长，但吞吐量相对较低。

本项目的核心诉求是"高吞吐上报 + 可靠性 + 与大数据生态协同"，因此选用 Kafka；其 KRaft 模式免除了对 ZooKeeper 的依赖，简化了单机容器部署。

### 1.2.2 分布式存储

面向不同数据形态，业界形成了"异构存储"的通行实践：

**分布式文件系统**方面，Hadoop HDFS 采用 NameNode 与 DataNode 分离的主从架构，NameNode 负责元数据管理、DataNode 负责数据块存储，专为"一次写入、多次读取"的大文件高吞吐顺序访问场景设计。其**元数据与数据分离**的设计使得客户端可直接与 DataNode 通信而不必经由 NameNode 中转，避免 NameNode 成为集群瓶颈——这一设计思想对本项目的接口实现有直接影响（详见 5.2.3）。备选方案 MinIO 部署更轻量，但偏离课程考核组件范围。

**分布式数据库**方面，MongoDB 采用文档模型（BSON），支持灵活的字段结构与丰富的查询语义；HBase 基于列族宽表模型，依赖 HDFS 与 ZooKeeper，适合超大规模稀疏数据。本项目结构化数据体量适中，查询以"按设备编号、时间范围"为主，MongoDB 更为贴合。值得注意的是，MongoDB 5.0 起引入的**时序集合（Time Series Collection）** 针对带时间戳的测量数据做了专门的存储优化（按 metaField 分组、按 granularity 分桶压缩），并支持 TTL 自动过期，是本项目遥测数据存储的关键技术。

### 1.2.3 分布式检索引擎

Elasticsearch 基于 Lucene 构建倒排索引，天然支持全文检索、结构化过滤、地理检索与聚合分析，是日志与事件检索领域的事实标准。其索引分片（Shard）机制支持水平扩展，副本（Replica）机制提供高可用。配合 Kibana 可快速构建可视化仪表盘。

在本项目中，Elasticsearch 承担的是"检索副本身份"——权威数据存于 MongoDB，ES 仅保存可重建的检索副本。这种**双写 + 以主存储为准**的模式，是业务数据库与搜索引擎协同的常见工程实践。

### 1.2.4 负载均衡与网关

Nginx 以其高并发、低资源占用、配置简洁的特点，成为反向代理与负载均衡的事实标准。在前后端分离架构中，Nginx 通常同时承担静态资源托管与 API 反向代理两个职责，是系统唯一的对外入口。

### 1.2.5 容器化部署

Docker 通过镜像封装应用及其运行环境，有效解决了"在我机器上能跑"的环境一致性问题。对于本项目这类需要同时运行六类中间件的场景，容器化的价值尤为突出：各组件的依赖与版本被封装隔离，避免混装冲突；Docker Compose 提供了声明式编排能力，一条命令即可启动整套环境；容器的删除重建成本极低，便于反复排错与重置。

## 1.3 项目主要研究内容

本项目的研究与实现内容按"需求—架构—实现—验证"的主线展开，具体包括以下六个方面。

### 1.3.1 需求分析与模块划分

以参与者驱动的方法识别系统边界与参与者（巡检值班员、系统管理员、系统运维人员，以及无人机、机器狗两个外部仿真模块），梳理用例清单与核心用例规格，并据此划分功能模块与技术支撑模块。

### 1.3.2 总体架构与技术选型

设计分层架构，明确设备仿真层、消息中间件层、业务服务层、分布式存储层、检索分析层、网关层与可视化展示层的职责边界与依赖方向；对容器化、文件系统、数据库、消息中间件、检索引擎、网关、后端语言、前端框架逐项进行方案比选并给出选型理由。

### 1.3.3 设备仿真模块实现

以软件方式模拟无人机与机器狗的运行行为，包括设备注册、周期心跳、位置轨迹、环境传感、影像元数据生成与告警事件触发，并实现任务指令的接收、执行与分阶段回执。

### 1.3.4 平台业务服务实现

实现消息消费与数据入库、设备状态维护与离线检测、任务创建下发与执行跟踪、告警生成处置与检索、影像归档与管理、统计分析与用户权限控制等功能，并设计分层结构以保证可维护性。

### 1.3.5 分布式存储与检索实现

实现结构化数据入 MongoDB（含时序集合建模与索引设计）、影像文件入 HDFS（基于 WebHDFS 协议）、告警事件入 Elasticsearch（按天滚动索引）的三路存储写入，以及对应的读取、检索与聚合分析接口。

### 1.3.6 系统测试与容量评估

完成功能测试与接口测试，并在此基础上开展**容量压测实验**：通过逐级加压测量系统的消息吞吐、资源占用与积压情况，定位系统瓶颈，并给出容量与资源的换算关系及优化建议。

## 1.4 报告组织结构

本报告共分七章，组织结构如下：

**第 1 章 绪论**，阐述项目的研究背景、行业现状、主要研究内容与报告结构。

**第 2 章 相关技术基础**，介绍项目所使用的六类技术组件的原理与特点，包括 Hadoop HDFS、MongoDB、Apache Kafka、Nginx、Elasticsearch 与 Docker。

**第 3 章 系统需求分析**，描述业务场景，分析功能性需求与非功能性需求，进行可行性分析，并给出业务流程与用例模型。

**第 4 章 系统总体设计**，说明系统设计原则、总体架构、技术选型、模块划分、数据库设计与部署方案。

**第 5 章 系统详细设计与实现**，按模块说明具体实现方案、关键代码与设计要点，并总结实践过程中遇到的关键问题及其解决方案，附系统运行效果截图。

**第 6 章 系统测试与优化**，说明测试环境与目标，给出功能测试、接口测试与性能测试的结果，并总结优化措施。

**第 7 章 总结与展望**，总结项目完成情况与实践收获，分析系统存在的不足，并给出后续改进与演进方向。

报告末尾附参考文献与三个附录：核心源代码片段、中间件主要配置文件、小组分工说明。
