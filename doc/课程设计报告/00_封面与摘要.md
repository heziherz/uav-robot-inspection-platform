## 摘要

本文面向园区安防场景，设计并实现了一套无人机-机器狗空地协同巡检集成平台。系统模拟"无人机高空巡查发现线索、机器狗地面抵近复核"的巡检业务闭环，综合运用分布式中间件、分布式存储、分布式检索引擎与负载均衡网关完成企业级应用集成。

系统采用 Docker Compose 单机容器编排，部署 Hadoop HDFS、MongoDB、Apache Kafka、Elasticsearch + Kibana、Nginx 等六类强制组件共 10 个容器（含 2 个业务服务实例与设备仿真端）。设备侧以独立进程运行的仿真模块扮演无人机与机器狗，通过**消息通道**上报状态与接收指令、通过**文件通道**自行上传影像，两条通道分离，平台不访问设备文件系统，从而真实还原了外部设备接入的边界语义。平台侧采用 Spring Boot 实现消息消费、业务处理、存储读写与 REST 接口；前端采用 React + Vite + Ant Design，配合 ECharts 与 Leaflet 实现统计分析、设备态势与告警可视化。

系统实现了设备注册接入、心跳与在线状态维护、巡检数据上报入库、任务创建下发与回执跟踪、告警生成与处置、多条件检索与聚合统计、影像归档与预览、三角色权限控制等完整功能。其中针对海量时序数据采用了 MongoDB 时序集合与攒批写入模式，针对影像大文件采用了 WebHDFS 与 HDFS 分离存储，针对告警检索采用了 Elasticsearch 按天滚动索引与聚合分析。

在此基础上，本项目完成了容量压测与瓶颈定位：实测发现消息中间件的分区数构成系统消费并行度的硬上限，并据此给出了优化路径。实践过程覆盖了多组件版本兼容、容器网络寻址、跨系统路径差异等典型集成问题，锻炼了分布式系统的部署调试与问题排查能力。

## Abstract

This paper designs and implements an air-ground collaborative inspection integration platform for unmanned aerial vehicles (UAVs) and robot dogs, targeting campus security scenarios. The system simulates an inspection workflow in which UAVs discover suspicious targets from high altitude and robot dogs perform close-range ground verification, integrating distributed middleware, distributed storage, a distributed search engine, and a load-balancing gateway to achieve enterprise-level application integration.

The system is deployed via Docker Compose on a single host, orchestrating eight containers covering six mandatory component categories: Hadoop HDFS, MongoDB, Apache Kafka, Elasticsearch with Kibana, and Nginx. On the device side, independently running simulator modules act as UAVs and robot dogs, interacting with the platform exclusively through the message middleware rather than connecting directly to databases, thereby faithfully reproducing the boundary semantics of external device access. On the platform side, Spring Boot implements message consumption, business processing, storage read/write, and REST interfaces, while the front end built with React, Vite, and Ant Design, together with ECharts and Leaflet, delivers statistical analysis and device situation visualization.

The system implements device registration, heartbeat and online-status maintenance, inspection data ingestion, task creation, dispatch and acknowledgement tracking, alarm generation and handling, multi-condition retrieval and aggregation, image archiving and preview, and three-role access control. MongoDB time-series collections with batched writes are adopted for high-volume telemetry, WebHDFS with separated storage is used for large image files, and daily rolling indices with aggregations are applied to alarm retrieval.

Furthermore, capacity stress testing and bottleneck identification were performed. Measurements reveal that the partition count of the message middleware constitutes a hard ceiling on consumption parallelism, based on which an optimization roadmap is proposed. The practice covers typical integration issues including multi-component version compatibility, container network addressing, and cross-system path discrepancies, exercising the ability to deploy, debug, and troubleshoot distributed systems.

**Key words**: UAV-robot dog collaboration; enterprise application integration; message middleware; distributed storage; Elasticsearch; Nginx
