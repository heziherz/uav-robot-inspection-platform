# 无人机-机器狗空地协同巡检集成平台 —— 仿真数据与消息契约说明

| 项目 | 内容 |
| :--- | :--- |
| 文档定位 | 《需求分析文档.md》的**补充说明**：专门定义“仿真设备数据”的分类、字段、消息契约、存储去向与可靠性要求 |
| 服务对象 | 仿真模块负责人、后端业务开发、中间件运维、测试与文档负责人 |
| 编号体系 | 沿用《需求分析文档.md》：参与者 A1~A5、用例 UC-01~UC-41、模块 M1~M7 / T1~T4 |
| 技术前提 | 消息中间件 Kafka、结构化存储 MongoDB、大文件 HDFS、检索 Elasticsearch（选型见《需求分析与总体架构技术选型.md》） |

> **说明**：本文档是**数据层面的单一契约来源**。仿真模块、业务服务、存储与检索引擎的实现都以本文档的字段与 Topic 定义为准；字段如需变更，走“变更记录”并同步各方。

---

## 1 目的与范围

回答四个问题：

1. 仿真设备**产生哪些数据**、长什么样（字段与格式）；
2. 这些数据**怎么流转**（Topic、方向、分区键）；
3. 数据**存到哪里**（MongoDB 集合 / ES 索引 / HDFS 路径）；
4. 大数据量与异常情况下**怎么保证不丢、不重、不乱**。

**不在范围内**：真实硬件协议（无人机飞控、机器狗运动控制）、真实视频流处理（以关键帧图片 + 元数据代替）。

## 2 数据来源与角色

```text
A4 无人机仿真模块 ─┐
                   ├─(仅经 Kafka)─→ 业务服务(M1/M2/M3) ─→ MongoDB / HDFS / ES
A5 机器狗仿真模块 ─┘                        ↑
                                      A1 值班员（经 Nginx 查询/操作）
```

| 角色 | 在数据链路中的职责 | 约束 |
| :--- | :--- | :--- |
| A4 / A5 仿真设备 | **生产者**：生成并发送心跳、位置、传感器、影像元数据、告警、任务回执 | **只连接 Kafka**；不直连数据库、不直连 HDFS |
| 业务服务（M1/M2/M3） | **消费者 + 写入中枢**：消费消息、落库、写索引、必要时读文件写 HDFS | 所有存储读写收敛在此层 |
| 检索引擎（T3） | 提供检索与聚合 | 只存**可检索字段**，不存大文件 |
| HDFS（T2） | 存影像**文件本体** | 由业务服务写入；仿真端只提供 `localPath` |

> **约束的意义**：设备侧不持有任何存储凭据，也不了解存储选址；存储策略（目录、命名、副本、清理）集中在业务层统一治理 —— 这与架构图中 `SIM → MQ` 单向箭头一致。

## 3 数据总体特点与设计含义

| # | 特点 | 由此确定的设计 |
| :--- | :--- | :--- |
| 1 | 多源异构（无人机 / 机器狗字段不同） | JSON 半结构化；MongoDB 文档模型 |
| 2 | 流式、时序（持续产生、带时间戳） | 消息队列 + 时序化存储；按时间范围查询 |
| 3 | **体量悬殊**：元数据 KB 级，影像文件 MB 级 | **元数据走 MQ、文件走 HDFS**，用 `fileId` 关联 |
| 4 | 高频、单条小（心跳 5s、遥测 1s） | 优化吞吐：分区、批量、异步 |
| 5 | 周期性与突发性并存（心跳规律 / 告警突发） | 同一通道承载多类型，靠 `msgType` 区分 |
| 6 | **可靠性要求分级**（心跳可丢 / 告警不可丢） | 分级策略：告警类 `acks=all` + 幂等 + 重试 |
| 7 | **两类语义并存**：状态=最新值，事件=历史追加 | 存储分两种：**upsert（设备状态）** / **append（轨迹、告警）** |
| 8 | 重复与乱序（重试、并发） | `msgId` 幂等键；分区键 `deviceNo` 保证单设备有序 |
| 9 | 带地理属性 | 坐标存为 `geo_point`，支持地理检索 |
| 10 | 设备时钟不可信 | 双时间戳：`eventTime`（设备产生）+ `ingestTime`（平台接收） |
| 11 | 仿真需贴近真实协议语义 | 保留注册 / 心跳 / 上报 / 回执交互语义 |
| 12 | 不做真实视频流 | 以“关键帧图片 + 视频元数据”替代 |

## 4 数据分类与字段定义

### 4.1 上行数据（设备 → 平台）

#### (1) 心跳数据 Heartbeat

| 项 | 内容 |
| :--- | :--- |
| 用途 | 维持在线状态、监控电量与故障（UC-02、UC-05） |
| Topic / 频率 | `topic_device_heartbeat` / 默认 **5 秒** |
| 存储 | MongoDB `device_status`（**upsert，一台设备一条**） |
| 可靠性 | 普通（允许偶发丢失，下一条覆盖） |

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| msgId | string | ✔ | 消息唯一 ID（幂等键） |
| deviceNo | string | ✔ | 设备编号，如 `UAV-001` |
| deviceType | string | ✔ | `DRONE` / `ROBOT_DOG` |
| battery | int | ✔ | 电量 0~100 |
| status | string | ✔ | `ONLINE` / `OFFLINE` / `FAULT` |
| eventTime | long | ✔ | 设备产生时间（毫秒时间戳） |

```json
{"msgId":"MSG-20260909-0001","deviceNo":"UAV-001","deviceType":"DRONE",
 "battery":87,"status":"ONLINE","eventTime":1788928949685}
```

#### (2) 位置 / 轨迹数据 GPS

| 项 | 内容 |
| :--- | :--- |
| 用途 | 地图态势、轨迹回放、地理检索（UC-11、UC-16） |
| Topic / 频率 | `topic_device_gps` / 默认 **1 秒** |
| 存储 | MongoDB `telemetry`（**append 追加**）；坐标同步 `geo_point` |
| 可靠性 | 普通（可抽样降频） |

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| msgId / deviceNo | string | ✔ | 同上 |
| taskId | string | ✖ | 关联任务（执行中时携带） |
| lat / lng | double | ✔ | 纬度 / 经度（WGS84） |
| altitude | double | ✖ | 高度（米）；无人机 50~120，机器狗 0 |
| speed | double | ✖ | 速度（米/秒） |
| heading | double | ✖ | 航向角（度） |
| eventTime | long | ✔ | 产生时间 |

```json
{"msgId":"MSG-...","deviceNo":"UAV-001","taskId":"TASK-20260909-01",
 "lat":29.5621,"lng":106.5503,"altitude":60.0,"speed":8.5,"heading":95.0,"eventTime":...}
```

#### (3) 传感器 / 运行数据 Sensor

| 项 | 内容 |
| :--- | :--- |
| 用途 | 环境与设备健康监控，触发阈值告警（UC-02、UC-41） |
| Topic / 频率 | `topic_device_sensor` / 默认 **5 秒**（机器狗为主） |
| 存储 | MongoDB `sensor_data`（append） |
| 可靠性 | 普通 |

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| msgId / deviceNo | string | ✔ | 同上 |
| temperature | double | ✖ | 环境温度（℃） |
| humidity | double | ✖ | 湿度（%） |
| gasValue | double | ✖ | 可燃气体浓度（ppm） |
| deviceTemp | double | ✖ | 设备自身温度（℃） |
| eventTime | long | ✔ | 产生时间 |

#### (4) 影像元数据 Media Meta（**与文件分离**）

| 项 | 内容 |
| :--- | :--- |
| 用途 | 关联巡检影像证据；供检索与前端展示（UC-03、UC-14） |
| Topic / 频率 | `topic_device_media_meta` / 默认 **10 秒**（或按任务节点） |
| 存储 | MongoDB `media_meta`（append）；**文件本体由业务服务写入 HDFS** |
| 可靠性 | **较高**（证据类，允许重试） |

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| msgId / deviceNo | string | ✔ | 同上 |
| fileId | string | ✔ | 影像唯一 ID（与 HDFS 文件名关联） |
| taskId | string | ✖ | 关联任务 |
| fileType | string | ✔ | `JPG` / `INFRARED` / `VIDEO_FRAME` |
| size | long | ✔ | 文件大小（字节） |
| localPath | string | ✔ | **仿真端本地路径**（业务服务据此读取并上传） |
| hdfsPath | string | ✖ | 上传成功后由业务服务回填 |
| lat / lng | double | ✖ | 拍摄位置 |
| eventTime | long | ✔ | 拍摄时间 |

```json
{"msgId":"MSG-...","deviceNo":"UAV-001","fileId":"IMG-000123","fileType":"JPG",
 "size":524288,"localPath":"sim-files/IMG-000123.jpg","lat":29.56,"lng":106.55,"eventTime":...}
```

#### (5) 告警事件 Alarm

| 项 | 内容 |
| :--- | :--- |
| 用途 | 隐患发现与处置闭环（UC-41 生成、UC-14 展示、UC-15 处置） |
| Topic / 频率 | `topic_device_alarm` / **触发式**（按规则或概率） |
| 存储 | MongoDB `alarm`（append）+ **ES `alarm-YYYY.MM.DD`**（可检索） |
| 可靠性 | **强**（`acks=all` + 幂等 + 重试；不可丢） |

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| msgId / deviceNo | string | ✔ | 同上 |
| alarmId | string | ✔ | 告警唯一 ID（消费侧幂等键） |
| alarmType | string | ✔ | 见 §11 枚举（如 `INTRUSION`） |
| level | string | ✔ | `INFO` / `WARN` / `CRITICAL` |
| lat / lng | double | ✖ | 告警位置 |
| mediaFileId | string | ✖ | 关联证据影像 |
| description | string | ✖ | 描述 |
| eventTime | long | ✔ | 发生时间 |

#### (6) 任务回执 Task Ack

| 项 | 内容 |
| :--- | :--- |
| 用途 | 任务状态推进与闭环（UC-04、UC-13） |
| Topic / 频率 | `topic_device_task_ack` / 触发式（开始 / 完成 / 失败） |
| 存储 | MongoDB `task_log`（append）；任务状态更新 `task`（upsert） |
| 可靠性 | **强** |

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| msgId / deviceNo | string | ✔ | 同上 |
| taskId | string | ✔ | 关联任务 |
| stage | string | ✔ | `STARTED` / `PROGRESS` / `FINISHED` / `FAILED` |
| progress | int | ✖ | 进度 0~100 |
| remark | string | ✖ | 失败原因 / 备注 |
| eventTime | long | ✔ | 时间 |

### 4.2 下行数据（平台 → 设备）

#### 任务指令 Command（含抵近复核指令）

| 项 | 内容 |
| :--- | :--- |
| 用途 | 下发巡检 / 复核任务（UC-12、UC-15 的 include） |
| Topic | `topic_platform_command`（**唯一的下行 Topic**） |
| 生产者 / 消费者 | 业务服务 / A4、A5 仿真设备 |
| 存储 | MongoDB `task`（任务记录） |
| 可靠性 | **强**（失败需可重发） |

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| msgId | string | ✔ | 指令 ID（**设备侧按此幂等，避免重复执行**） |
| taskId | string | ✔ | 任务编号 |
| deviceNo | string | ✔ | 目标设备 |
| taskType | string | ✔ | `ROUTINE` 例行 / `SPECIAL` 专项 / `REVIEW` 抵近复核 |
| area / route | string | ✖ | 巡检区域 / 路线 |
| points | array | ✖ | 目标点位坐标（复核任务必填） |
| issueTime | long | ✔ | 下发时间 |

```json
{"msgId":"CMD-...","taskId":"TASK-20260909-02","deviceNo":"DOG-001",
 "taskType":"REVIEW","points":[{"lat":29.5621,"lng":106.5503}],"issueTime":...}
```

## 5 消息通用规范

| 规范项 | 约定 |
| :--- | :--- |
| 序列化 | JSON（UTF-8）；字段名 camelCase |
| 时间 | 毫秒级 `long` 时间戳；`eventTime` 设备产生、`ingestTime` 平台接收（由业务侧补） |
| 坐标 | WGS84，`lat` / `lng` 分开字段；ES 中映射为 `geo_point` |
| 消息信封 | 每条消息必须含 `msgId`、`deviceNo`、`eventTime`、`msgType` |
| 幂等键 | `msgId`（通用）；告警另用 `alarmId`；任务另用 `taskId` |
| 分区键 | 统一 `deviceNo` —— 保证**同一设备消息严格有序** |
| 消息大小 | 单条建议 < 100KB；影像/视频文件**绝不走消息** |
| 枚举值 | 统一下划线大写（见 §11 字典） |
| 版本 | 预留 `version` 字段（如 `v1`），便于协议演进 |

### 7.1 影像“文件 / 元数据”分离规范

```text
仿真端：生成占位图片 → 本地目录 sim-files/{fileId}.jpg
        ↓ 只发元数据（含 localPath、size）
业务服务：消费 → 读取本地文件 → 上传 HDFS
        ↓ 回填 hdfsPath
MongoDB media_meta（含 hdfsPath） + ES 索引（可检索字段）
```

| 规范项 | 约定 |
| :--- | :--- |
| HDFS 目录 | `/uav/media/{deviceNo}/{yyyyMMdd}/{fileId}.{ext}` |
| 关联键 | `fileId`（元数据 ↔ 文件 ↔ 告警证据） |
| 上传失败 | 记录失败日志 + 支持重传（幂等：同 `fileId` 覆盖） |
| 清理 | 超期文件按目录批量归档/删除（演示级手动） |

## 8 可靠性、一致性与幂等

### 8.1 可靠性分级

| 级别 | 适用消息 | Kafka 生产者配置 | 允许丢失 |
| :--- | :--- | :--- | :---: |
| **强** | 告警、任务回执、下行指令 | `acks=all`、`enable.idempotence=true`、`retries>0` | ❌ 不允许 |
| **普通** | 心跳、位置、传感器 | `acks=1`、幂等可选 | ⚠️ 允许偶发（可被下一条覆盖） |
| **高** | 影像元数据 | 同“强”（证据类） | ❌ 不允许 |

### 8.2 幂等与去重

| 场景 | 键 | 策略 |
| :--- | :--- | :--- |
| 消息重复投递 | `msgId` | 消费侧记录/校验，重复直接跳过 |
| 告警重复 | `alarmId` | MongoDB 以 `alarmId` 为 `_id`，重复写入=覆盖 |
| 任务重复下发 | `taskId` + `msgId` | 设备侧按 `msgId` 幂等，避免重复执行 |
| 设备状态 | `deviceNo` | upsert，天然幂等 |

### 8.3 乱序与时钟

- **同设备保序**：分区键 = `deviceNo`，Kafka 分区内有序 → 消费顺序 = 产生顺序；
- **跨设备无序**：不要求定序（各设备独立）；
- **双时间戳**：以 `ingestTime` 作为平台侧统一时间基准，避免设备时钟漂移导致时序错乱；
- **迟到的告警**：按 `eventTime` 归档，不因到达晚而丢弃。

### 8.4 消费失败处理

```text
消费异常 → 本地重试（有限次） → 仍失败：写入失败日志/死信 → 告警运维人员
          （禁止无限阻塞分区，避免整条链路卡死）
```

## 9 数据量与容量估算（演示规模）

| 项 | 假设 | 计算 |
| :--- | :--- | :--- |
| 设备数 | 3 台无人机 + 3 台机器狗 | 6 台 |
| 心跳 | 5 秒/台 | 6 ÷ 5 ≈ **1.2 条/秒** |
| 位置 | 1 秒/台 | **6 条/秒** |
| 传感器 | 5 秒/台 | ≈ 1.2 条/秒 |
| 影像元数据 | 10 秒/台 | 0.6 条/秒 |
| 合计 | — | **约 9 条/秒 ≈ 78 万条/天** |
| 单条大小 | 约 300 B | 日增 ≈ 220 MB（元数据） |
| 影像文件 | 200 KB/张，0.6 张/秒 | 日增 ≈ 10 GB（HDFS） |

**放大 10 倍时（60 台设备）的应对**：提高分区数、开启生产端批量、`refresh_interval` 调大、按天滚动索引 + ILM 清理、影像文件生命周期管理。

## 11 附录 A：枚举字典
